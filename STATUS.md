## What is in each commit

**Commit 1, the catalog generalisation.** Separable and PR-sized on its own. `Uf2Build` gains
`board_id_prefix`, a new `Uf2BoardIdPrefix` domain value owns the normalisation rule, the
validator's `mount_label != "TECHOBOOT"` clause becomes a non-empty check, and the flasher's
`techo.rs` becomes `uf2.rs` with identity read from the catalog. Two new catalog tests, one new

**Commit 2, stages A and B of the refactor.** `t-echo` the binary crate becomes
`personal-hopspot-nrf52840` the library plus `boards/t-echo` (`hopspot-t-echo`) the binary.
`src/hopspot/*` flattens to `src/`, `ssd1681.rs` moves under `src/panels/`, the `Nrf52840Board`
trait lands in `src/board.rs`, and everything T-Echo-specific moves to `src/boards/t_echo.rs`.
`memory.x` becomes `memory-s140-7.x`, staged per board binary by `boards/nrf_build.rs`.
`TechoStorage` and `TechoPersistence` become `Nrf52840Storage` and `Nrf52840Persistence`.
Release plumbing that the workspace conversion breaks is fixed in the same commit: the flasher's
cargo invocation gains `-p` from the catalog package field, `boards.json` renames the package to
`hopspot-t-echo`, and `validation/platforms/embedded.sh`, `.github/workflows/ci.yml`, and
`tools/device/techo-flash.sh` build the board package explicitly.

**Commit 3, stage C.** `src/panels/st7789.rs` (the hand-written driver), the
`src/boards/heltec_t114.rs` board module with the verified pin map, `boards/heltec-t114`
(`hopspot-heltec-t114`), the `ANIMATION_CLOCK` trait const, the `SPI3` interrupt binding, and a
`lit: Level` parameter on the shared panel-light task.

**Commit 5, the review fix.** `embassy_nrf::spim::Spim::new` takes its pins as sck, miso, mosi,
in that order (checked against the embassy-nrf 0.10.0 docs). The T-Echo's deferred-pin fields
were named mosi-then-miso but passed positionally, so every pin landed in the correct slot and
the names were the lie: P0.23 fills the miso slot and is the SX1262's MISO, P0.29 fills the mosi
slot and is the e-ink's SDI, exactly as the Meshtastic t-echo variant spells them. The T114
board module named its fields truthfully from the pin map and copied the T-Echo call's visual
order, which put MOSI P0.22 into the miso slot and MISO P0.23 into the mosi slot: a radio that
can never answer, plus the SPIM driving P0.23 against the SX1262's own MISO output whenever NSS
is low. The fix renames the T-Echo fields to the SPIM role each pin actually fills, with every
pin kept in the same slot as before, and passes the T114's pins in the constructor's order.
Every SPIM call site in both board files now reads sck, miso, mosi.

## T114 flashing procedure (from the verified pin map)

1. Enter DFU by double-tapping RESET (the bootloader also declares 1200-baud touch).
2. Read the bootloader's identity verbatim before anything else:

   ```powershell
   Get-Volume | Where-Object { $_.DriveType -eq 'Removable' } | Select-Object DriveLetter, FileSystemLabel
   Get-Content <drive>:\INFO_UF2.TXT
   ```

   Expected from Heltec's shipped bootloader image:

   ```text
   UF2 Bootloader 0.9.0-2-g836c8dc-dirty lib/nrfx (v2.0.0) lib/tinyusb (0.12.0-145-g9775e7691) lib/uf2 (remotes/origin/configupdate-9-gadbb8c7)
   Model: HT-n5262
   Board-ID: HT-n5262
   SoftDevice: S140 6.1.1
   ```

3. **The stock bootloader cannot run this firmware.** S140 6.1.1 puts the application at
   0x26000; `nrf-softdevice` binds S140 v7, and this branch links at 0x27000. Copying a Prns UF2
   onto a stock T114 gives a board that copies the file, reboots, and does nothing. The board
   must first be re-bootloadered with an `Adafruit_nRF52_Bootloader` port for the T114 built with
   `SD_VERSION = 7.3.0` (the community OTAFIX repo's `src/boards/heltec_t114/board.h` is most of
   that port; upstream already vendors `s140_nrf52_7.3.0`). Deliver the new bootloader as a
   bootloader-update UF2 copied onto the stock drive.
4. **Never chip-erase this board.** UICR holds the bootloader start pointer (`NRFFW[0]` =
   0xF4000) and, programmed at runtime, `PSELRESET`. A chip erase takes out the reset button and
   the bootloader in one stroke; recovery is SWD only, on header P1 pins 9 and 10.
5. After re-bootloadering: build `hopspot-heltec-t114`, objcopy the ELF to a raw binary, then
   `python3 tools/device/bin2uf2.py <bin> <uf2> 0x27000 0xADA52840`, and copy the UF2 to the
   mounted drive. The drive disappears when the device reboots.
6. First-light triage, in order of likelihood: a dark panel with a live CPU is the reset state,
   not a fault (rail and backlight are both active low and off until driven); an image shifted by
   tens of pixels is the 40/52 window origin (try 53); a mirrored image is the rotation variant,
   and the row offset moves to 53 with it; a photographic negative is the inversion flag; swapped
   red and blue is the colour order.

## Deviations from the planning documents (the tree won)

- Board type names use the tree's existing `Techo` prefix (`TechoBoard`, `TechoDisplay`,
  `TechoDeferredHardware`), not the `TEcho` spelling some planning text used.
- `drive_panel_light` gained a `lit: Level` parameter. The plan assumed the T114 backlight
  differed only in hold time; the verified schematic shows it behind an active-low P-FET while
  the T-Echo frontlight is active high, so polarity became a parameter when the second user
  arrived.
- The T114 board module was rewritten against the delivered ST7789 driver API
  (`PanelConfig`/`PanelFrame`/`Palette`) and the verified pin map; the earlier board sketch had
  provisional pins and a different driver contract, and its compile-blocking guard was dropped
  because the map is now multi-source confirmed. The battery probe became
  `T114Battery { adc, gate }` since the divider gate on P0.06 is confirmed.
- `panels` is a `pub` module with `st7789` pub. CI compiles with `-D warnings`, and the driver's
  configuration variants a single board does not construct (`CounterClockwise`, `Bgr`, `Normal`)
  would otherwise be dead-code errors. This was the reachability outcome the driver notes
  anticipated.
- The board is deliberately not in `SHIPPING_BOARD_SLUGS`, `boards.json`, the website, or
  `shipping-firmware.sh`. It does not ship until the bootloader story is settled and the panel
  has seen first light; the shipping gate stays a conscious edit.
- `doctor_mount_from` filters candidates to the selected board's prefix before selecting, one
  step beyond the catalog plan's sketch. Behaviour-preserving with one UF2 board cataloged.
- `tools/device/techo-flash.sh` needed the `-p` treatment too; the plan missed it.
- `audits/unsafe-snapshot.json` and `THIRD_PARTY_NOTICES.md` were hand-edited (package rename
  plus two zero-unsafe board packages), not regenerated. If `unsafe-audit.py` or the notices
  generator diff, regenerate with the real tools; the guessed fields are the `graphs` feature
  lists.
- The shared `softdevice_config` still selects the internal RC LF clock. Both boards fit
  32.768 kHz crystals, so switching to the crystal source is a real improvement, but it changes
  SoftDevice behaviour on the T-Echo too and belongs in its own change.

## Known gaps (deliberate, for the follow-on board work)

- The flasher build path still hardcodes the `t-echo.uf2` artifact name
  (`flasher/src/build.rs`, `cache/mod.rs`) and the release custody path assumes it. Blocking for
  shipping the T114, not for this branch.
- The T114's Board-ID is exactly `HT-n5262` with no revision suffix. The flasher's
  revision-shape rule requires a non-empty suffix after the cataloged prefix, so cataloging the
  T114 will need an exact-match allowance. Known, deferred to the board catalog entry.
- `DisplayPowerControl` stays `Unavailable` and the `OledOff` arm stays empty; making it real
  means deciding whether off is the backlight, the panel, or both, after the board boots.
- GNSS (P1.05/P1.07 UART, P1.06 reset, P1.02 standby, P1.04 PPS), the two SK6812s on P0.14, the
  Vext rail on P0.21, and both I2C buses are intentionally unclaimed on day one.
- The ST7789 driver deasserts CS between pixel bands (separate `SpiDevice` transactions, the
  same shape the SSD1681 uses). If bands ever tear on the glass, one transaction per band is
  the first fix.
- The 150 ms settle between panel rail-up and controller init is inherited from the T-Echo's
  bring-up margin, not a datasheet number.
- Backlight brightness is fixed by a series resistor that changed between board revisions
  (200R on V2.0, 56R on V2.1); firmware cannot equalise it beyond duty-cycling the enable pin.
